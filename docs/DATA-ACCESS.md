# Public data access

Alle's ClinX publishes selected product and document metadata as plain JSON and CSV files in this repository.

This is a **public data layer**, not a transactional API. Consumers should treat the repository as a version-controlled reference source and should always defer to current controlled product documentation for safety-critical decisions.

## Primary datasets

| Dataset | Format | Purpose |
| --- | --- | --- |
| `data/products.json` | JSON | Curated product metadata and links to public product documents |
| `data/products.csv` | CSV | Tabular product dataset for spreadsheets and data tools |
| `data/document-index.json` | JSON | Index of public PDFs mirrored in the repository |
| `data/document-register.csv` | CSV | Controlled-document register for the current public library |
| `data/release-manifest.json` | JSON | Integrity metadata, including SHA-256, file size and page count |
| `data/legacy-filename-map.csv` | CSV | Mapping from retired document filenames to canonical paths |

## Raw GitHub access

Machine-readable files can be consumed through GitHub's raw-content URLs.

Examples:

```text
https://raw.githubusercontent.com/alles-clinx/.github/main/data/products.json
https://raw.githubusercontent.com/alles-clinx/.github/main/data/document-index.json
https://raw.githubusercontent.com/alles-clinx/.github/main/data/products.csv
```

For reproducible integrations, pin requests to a commit SHA or release instead of relying indefinitely on `main`.

## Integrity

Published PDF hashes are available in `checksums.sha256`. The release manifest also records integrity and document metadata generated by repository QA.

## Stability

File structures may evolve as the public information model improves. Consumers should:

- tolerate additional JSON fields;
- avoid depending on undocumented field ordering;
- use canonical file paths rather than retired filenames;
- check the repository changelog before production integrations.

## Publication boundary

The public datasets intentionally exclude proprietary formulations, confidential supplier information, customer data, credentials and non-public commercial information.

See [PUBLIC-DATA.md](../PUBLIC-DATA.md) for the publication policy.
